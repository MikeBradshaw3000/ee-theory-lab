## The ruling

**1. Six masters, and the steps each binds.**

| Master | Drawn at the authorization of | Binds the jobs of | Kind |
|---|---|---|---|
| `calibration` | step 4 | step 4 (`calibration_census`); "never reused" | apparatus |
| `design` | step 7 | step 7 (`evaluator_design_audit`) | qualification |

The contract's table draws five; `benchmark` is added by this ruling because step 10 runs dynamics and the contract assigns it no stream. Steps 12 and 13 each have their own authorization (§8: one per step) and cite the canonical master drawn at step 11; they draw nothing. Every run has its own stream under §2.5 whatever master it is under. No master is used by a step outside its row.

**2. The derivation.** Let `stage` be one of the six names above. Let `base_commit` be the 40-character lower-case hexadecimal id of the commit that is the only parent of the commit adding that stage's authorization file. Let `value` be 64 lower-case hexadecimal characters (32 bytes) that Mike generates at authorization (point 4). For n = 0, 1, …, 15:

    candidate(n) = the first 8 bytes, read as a big-endian unsigned integer, of
                   SHA-256( "ee-theory-lab|flight9|" + VERSION + "|master|" + stage + "|" + base_commit + "|" + value + "|" + decimal(n) )   (ASCII)

with VERSION the instrument's version string (`f9_stage1_v1`). **The master is candidate(n) for the least n from 0 to 15 at which it is admissible:** at least 1,000,000; not a retired master; and not a registered Flight 9 master (point 3). If no n from 0 to 15 is admissible the derivation FAILS: no master exists, nothing runs, and the matter goes to Mike. (One candidate is below 1,000,000 with probability about 5e-14.)

**3. Registered masters.** The registered Flight 9 masters, for a given base commit, are the masters stated in every Flight 9 authorization file present in that commit. The set is read from the append-only registry in the base commit; it does not depend on any order of stages. A stage that was authorized has used its master, whether or not its jobs completed.

**4. Mike's value.** It is generated on the canonical machine by the operating system's cryptographic random generator, by the authorization kit's script, after the base commit is on the remote `main`, once, and the first value generated is the one used. It is written into the authorization file and is public from that commit on. L1 builds the kit before the value exists and does not see it until the authorization is pushed.

**5. The base commit is on the remote `main` before the authorization is written,** and it contains: the frozen contract; the instrument of record; the `build_identities` record (§8 step 1) with the instrument version identity; and the record of every step the stage requires (§8, "Requires"). The authorization commit adds the authorization file and nothing else.

**6. What the authorization file states, and what the runner verifies.** The file states the stage, the step and jobs, the base commit, Mike's value, n, the master, the contract's SHA-256 and the instrument version identity from `build_identities`. A job of record runs only if the runner, from a clone, finds that: the authorization commit's only parent is the stated base commit; the derivation of point 2, with the registered set of point 3, gives the stated n and master; the master is not a test master; the contract in the working tree has the stated SHA-256; the instrument source in the working tree has the identities the `build_identities` record states; and the job belongs to that master's row in point 1. Recomputing the hash is not sufficient by itself.

**7. One draw per stage.** Under one instrument version a stage is authorized once. A job interrupted by the machine and relaunched under the same authorization uses the same master; that is not a new draw. **A failed qualification closes the stage (§1.5 A5 and A7: "a failed qualification closes the stage"; §8 steps 7 to 9: "stage closes"): no replacement commit, value or master is drawn for it under that instrument version.** Any change to the instrument of record is a new instrument version with a new version string, a new `build_identities` record and new authorizations; this is a rule of governance, not a consequence of the formula.

**8. No preview.** Nobody computes a stage's master, or runs any job, ensemble or case under it or under a candidate for it, before that stage's authorization is committed. No commit, value or master is chosen, re-made or discarded in view of any outcome. The derivation makes most of this impossible for L1 (point 4) and checkable for the base commit (point 5); the rest is a rule of conduct and is stated as one.

**9. The retired list stays as placed (21).**

## What this secures, and what it does not

**Secured.**
- **Reproducible.** Anyone with a clone can recompute every master from the authorization file and check it against the commit it sits on.
- **Bound to the instrument.** The base commit holds the instrument and every earlier record. A changed instrument is a different commit and a different master.
- **Not knowable before authorization by anyone who does not hold Mike's value,** L1 included. Mike's value does not exist until the authorization is made. Computing masters for candidate base commits in private, and pushing only a preferred one, gains nothing without it. In particular the design and held-out ensembles cannot be previewed while the qualification is being built or sealed.

**Not secured, stated plainly.**
- **It cannot be shown afterwards that Mike generated one value and used the first.** The record relies on him for that. The hash proves nothing about how the value was produced.
- **It does not hide the master after authorization.** From that commit on the master is public, and the stage's jobs then run under it.
- **It is a declared, checkable derivation with one unpredictable input. It is not a cryptographic commitment scheme and makes no claim to be one.**
- The first draft of this record said "Nobody chooses the number". That was wrong for the rule as first written (the base commit could be selected by whoever prepared it) and was L1's overstatement; L2 found it (governance round 1, D1).
